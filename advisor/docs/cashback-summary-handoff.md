# Месячная сводка КопиКэша

## Дизайн и фронтенд

Добавьте сводку за месяц на главную, используя текущие компоненты и токены. Пользователь видит итог по записанным покупкам сразу после открытия приложения. Ссылка на детали карт вторична. Для макета на 390 px используйте один ответ `GET /api/me/stats`:

```json
{
  "month": "2026-11",
  "count": 12,
  "actualCashbackKopecks": 48000,
  "actualCashbackCount": 8,
  "calculatedKopecks": 62000,
  "missedKopecks": 15000,
  "cards": [
    {"cardId":"a","name":"Карта А","count":7,"spentKopecks":900000,"cashbackKopecks":40000,"missedKopecks":11000,"actualCashbackKopecks":32000,"actualCashbackCount":5},
    {"cardId":"b","name":"Карта Б","count":5,"spentKopecks":670000,"cashbackKopecks":22000,"missedKopecks":4000,"actualCashbackKopecks":16000,"actualCashbackCount":3}
  ]
}
```

| Состояние | Что показать |
|---|---|
| Частичные подтверждения | «Получили 480 ₽», подпись «Подтверждено по 8 из 12 покупок». Рядом «По расчёту 620 ₽» и «Могли получить ещё 150 ₽». |
| Есть покупки, подтверждений пока нет | «Нет подтверждённых начислений». Расчёт и потенциальная прибавка доступны. |
| Подтверждён ноль | «Получили 0 ₽» с числом подтверждённых покупок. |
| Месяц пуст | «За этот месяц покупок пока нет» и переход к расчёту покупки. |
| Ошибка сети | Сообщение с действием «Повторить». Для загрузки предусмотрите состояние виджета. |

Для разбивки по картам подписывайте подтверждённые суммы и прогноз отдельно. Недополученный кэшбэк уже рассчитан сервером. Для интерактивного макета проверьте частичное подтверждение, пустой месяц и переход от отсутствующих данных к подтверждённым 0 ₽. Поля и правила описаны в [контракте](contract.md#месячная-сводка-кэшбэка).

## Задача для Hermes

Проведи независимую приёмку месячной сводки по коду ветки `feature/purchase-plan`. Используй отдельную чистую SQLite-базу и локальный FastAPI. Фронт ещё в работе, поэтому все проверки сейчас идут через API. Если исходники доступны только через GitHub, запроси актуальные коммиты локальной ветки.

1. Создай два аккаунта. В первом добавь две карты с 5% и 10% на кафе. Запиши три покупки по 1 000 ₽, две на первую карту и одну на вторую. Проверь **200 ₽ по расчёту** и **100 ₽ могли получить дополнительно**.
2. Подтверди начисления по первым двум покупкам как 0 ₽ и 48 ₽. Ожидай **48 ₽ по 2 из 3 покупок**. Проверь разбивку по обеим картам и что прогнозные 200 ₽ не изменились. Проверь редактирование и удаление подтверждения, переходы между `null` и 0 ₽.
3. Подтверди покупку предыдущего месяца в следующем месяце. Начисление должно войти в статистику месяца покупки. Во втором аккаунте добавь свою покупку и проверь, что она не попадает в итоги первого.
4. Сверь совместимость полей, которые уже читает профиль и журнал. Проверь, что повторная загрузка сводки сохраняет тот же результат и не создаёт покупок.

Верни фактические ответы API, команды для воспроизведения и дефекты с ожидаемым и наблюдаемым результатом. После подключения фронта повтори тот же сценарий с экрана 390 px.

## Интерфейс для приёмки

- На главной появился блок «Кэшбэк за месяц» под «Моими картами».
- Из заполненной сводки кнопка «Покупки за месяц» открывает нужный месяц журнала.
  В раскрытой покупке есть поле «Фактический кэшбэк, ₽».
- На 390 px проверь: сохранить 48 ₽, вернуться на главную, записать 0 ₽ и
  удалить отметку. При ошибке API введённая сумма должна остаться в поле.
  Сценарий включён в `tests/browser_mvp.py`.

Отдельный прогон с чистой тестовой базой:

```sh
python tests/browser_mvp.py --cashback-summary-only
```
