# Задачи и критерии сдачи

Стартовый репозиторий пуст. Рабочее предложение, не требование кейса: один FastAPI-сервис раздаёт API и HTML/CSS/JS; SQLite на постоянном диске. Если диск эфемерный — БД стенда. До установки зависимостей согласовать стек. Уточнить у организаторов дедлайн и часовой пояс, регламент защиты, допустимый хостинг, достаточность веб-ссылки и нужен ли APK при выборе PWA. Не откладывать проверку стенда до финала.

## P0-01 — категория и сумма → реальный топ-3

Первые 60 минут: подтвердить роли и среду, сверить [контракт и seed](contract.md), согласовать поля и зафиксировать контрольные ответы. Оценки ниже — трудозатраты первых задач после согласования, не дедлайны.

| Роль | Первое действие / зависит от | Принимаемый результат |
|---|---|---|
| Интеграция, владелец сдачи (1–2 ч) | Проверить доступ к стенду, диск, способ запуска | Воспроизводимый запуск, ранняя ссылка с телефона, проверенный рестарт; соединяет изменения ролей |
| Backend и тесты (2–4 ч) | Импорт seed и endpoint по контракту | Живой API считает B/A/C; отдельный тест проверяет отказ 422, повтор импорта не плодит данные |
| Frontend (2–4 ч) | Экран на примере ответа, затем подключение к API | На телефоне можно ввести сумму и выбрать категорию; видны рубли, причина, дата, загрузка и ошибки; в демо нет фикстуры вместо API |
| Продукт и приёмка (1–2 ч) | Независимо сверить ручные примеры и §10 кейса | На общей сборке проверены запрос, реальные ответы и смена категории; нарушения заведены как задачи |

## Следующие задачи — до сдачи

- **P0-02, каталог и условия** (бэк + фронт, после контракта): полный список шире топа, фильтр, экран условий, даты и применившееся ограничение. Проверяет приёмка на четырёх картах.
- **P0-03, мои карты** (бэк + фронт, нужны ID каталога): добавить, удалить, перечитать после reload, пересчитать в `mine`; проверить независимые браузеры и пустой набор.
- **P0-04, сдача** (владелец сдачи + приёмка, после P0-01–03): инструкция запуска и конфигурации, миграция/seed, сборка и тесты в CI, диагностические логи без секретов, порядок отката, ссылка и репетиция. Последнюю четверть доступного времени оставить на исправления. P1 открывается только после приёмки P0.

## Чек-лист приёмки (отмечать только после прогона)

- [ ] Супермаркеты, 2 500 ₽: B 150 ₽, A 100 ₽ (лимит), C 100 ₽, D 50 ₽. Топ B/A/C, полный B/A/C/D. На другой сумме, например 100 ₽, A лидирует без ограничения.
- [ ] 1,05 ₽ × 10% → 0,11 ₽. При равенстве A перед C, включая перестановку строк каталога и повтор запроса.
- [ ] Кафе, 2 500 ₽ → только D, 200 ₽. Ниже 100 ₽ правило кафе не подходит. АЗС → пустая выдача без ошибки. Ноль → 422, UI позволяет исправить сумму.
- [ ] На начальной дате правило действует, на конечной уже нет. Просрочка не выдается за актуальное предложение. Повтор импорта не меняет число строк, изменение ставки меняет расчёт; конфликт периодов не портит предыдущий каталог.
- [ ] Добавить A и C, перезагрузить: режим «Мои» возвращает только A и C. Повторное добавление не даёт дубля. В другом браузере список пуст, рестарт сервиса не стирает исходный список.
- [ ] Чистый запуск по README; стенд по ссылке на телефоне. Открыть полный список и дату условий, сменить категорию, переключить «Все / Мои». На сетевой ошибке не показывать старый топ как новый.

## Что показать жюри

Backend (критерии, стр. 1–2): воспроизводимый запуск, контракт API, результаты тестов, диагностика и восстановление. Frontend+Mobile (стр. 3): работающий мобильный интерфейс с настоящим API и понятными состояниями. Продукт (стр. 4): до оплаты покупатель видит, почему 6% дают на 50 ₽ больше, чем 10%, и сравнивает именно свои карты. Защита (стр. 5): короткая демонстрация этого пути, без заявления о фактических начислениях. Там же штрафы: −20% за отсутствие деплоя (APK для мобильной разработки), −30% за несоответствие минимуму кейса. Не выводить собственную формулу объединения штрафов.
