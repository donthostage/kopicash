# Ручной релиз на ВМ PROD

1. Сделайте консистентную резервную копию SQLite. Сохраните установленную конфигурацию, данные в `/var/lib/advisor` и `/etc/advisor.env`. Каталог данных должен принадлежать непривилегированному пользователю. Файл окружения храните с правами `0600`.
2. Соберите образы бэкенда и фронтенда из одного коммита. Dockerfile фронтенда принимает SHA через `--build-arg ADVISOR_REVISION=<SHA>`. Для Compose используйте `deploy/docker-compose.yml` и `deploy/docker-compose.frontend.yml`. Бэкенд получает SHA через `ADVISOR_REVISION` в конфигурации Compose.
3. Проверьте, какой процесс слушает порт 8766. Если на ВМ ещё работает старый установщик с `advisor-update.timer`, согласуйте его отключение перед переносом. Два экземпляра приложения с одной SQLite запускать нельзя.
4. Откройте `/healthz` и сверьте `revision` с SHA релиза. Запустите контрольный сценарий командой `python deploy/smoke.py http://127.0.0.1:8766 --revision <SHA> --require-frontend` из папки `advisor/`. После этого проверьте HTTPS с телефона.

Для подготовленных образов в Spirit Registry сохранён скрипт `deploy/spirit-release.sh`. Он запускается на ВМ вручную, проверяет оба контейнера и при сбое возвращается к предыдущей версии, если её конфигурация сохранена. При откате с несовместимой схемой восстановите соответствующую резервную копию SQLite.
